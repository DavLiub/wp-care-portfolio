# Telegram-гид WP Care

Бот помогает владельцу небольшого бизнеса выбрать разовую задачу или поддержку
WordPress и отправить заявку специалисту. Основа ответов — публичные страницы
Services и Pricing; внешние AI API не используются. Цены являются ориентиром.

## Запуск и проверка

Конфигурация: `.env.telegram` (не включать в Git). Нужны `TELEGRAM_BOT_TOKEN`
и `TELEGRAM_ADMIN_CHAT_ID`. Данные заявок обрабатываются только в личном чате.

```bash
docker compose -f docker-compose.telegram.yml build telegram-bot
docker run --rm --network none wp-care-portfolio-telegram-bot python -m unittest discover -s tests -q
docker compose -f docker-compose.telegram.yml up -d --no-deps telegram-bot
```

Запускайте один polling-контейнер на токен. Пересоздание контейнера сбрасывает
незавершённые диалоги, выбранный язык и ограничение частоты: данные хранятся
только в памяти. Коммит и слияние выполняются через принятый workflow проекта.

## Проверка в Telegram

1. `/start`, выбрать русский или английский, открыть цены и процесс.
2. Выбрать тариф, нажать «Оставить заявку». Проверить «Назад» и «Отмена».
3. Заполнить имя и email; неверный email и URL должны оставить текущий шаг.
4. Пропустить сайт кнопкой, описать задачу. До подтверждения заявка не отправляется.
5. Проверить сводку, исправить ответы через «Назад», нажать «Отправить заявку».
6. Проверить получение в администраторском чате и ответ пользователю отдельно.
7. Повторное нажатие после успеха не должно отправлять заявку снова.

При ошибке доставки заявка сохраняется в текущем диалоге для повтора; при сетевом
таймауте повтор может создать дубликат. Ограничение 60 секунд применяется после
успешной доставки. Пароли и ключи доступа не нужны для предварительной оценки.
Поля не обрезаются молча: имя до 120, email до 160, URL до 300, задача до 1200
символов. После отмены/главного меню черновик удаляется.

Тексты: `knowledge/<язык>/*.json`. После изменения условий на сайте обновить
оба языка и проверить тесты. Схема диалога: [SCENARIO.md](SCENARIO.md).

## База знаний и FAQ

`knowledge/<язык>/faq.json` содержит 12 вопросов в трёх группах. У каждого вопроса
есть `group`, `label`, `text`, `aliases` и `url`, у файла — `reviewed` (дата сверки).
Ключи вопросов и групп должны совпадать в двух языках. Источники — публичные
Services и Pricing; обещания, которых нет на сайте, не добавлять.

Для нового вопроса: добавить одинаковый ключ в оба языка, выбрать группу,
написать короткий ответ и точные разговорные формулировки в `aliases`, указать
источник и дату сверки. Проверить, что тарифы, часы и исключения согласованы
с `pricing.json` и `topics.json`. Запустить тесты и пересобрать бот.

Текстовые вопросы распознаются только по подготовленным формулировкам, на обоих
языках. Это работает вне формы заявки. Неизвестный вопрос получает меню для
выбора FAQ или обращения к специалисту. История вопросов пользователей не хранится.

Проверка: открыть FAQ, пройти каждую группу, вернуться к списку и перейти к заявке;
вне заявки отправить «Какой тариф выбрать?» и «What costs extra?», затем неизвестный
вопрос. Ответ должен использовать выбранный язык; неизвестный вопрос — показать меню.

## Подбор формата поддержки

Кнопка «Помогите выбрать» есть в главном меню, описаниях разделов и FAQ-ответах.
Вопросы и объяснения хранятся в `knowledge/<язык>/selection.json`; правила — в
`guide.py`, обработка шагов — в `bot.py`. Не менять внутренние ключи вариантов
без изменения правил и тестов. Три вопроса, кнопки назад/выхода и предварительная
рекомендация доступны на русском и английском.

Проверка: выбрать регулярную помощь → уход → один сайт, получить Complete
WordPress Care. Вернуться назад и выбрать несколько сайтов: должна появиться
индивидуальная оценка. Нажать «Оставить заявку»: ответы должны присутствовать
в первом вопросе, сводке и доставленной заявке. Назад с первого вопроса должен
вернуть к результату подбора. До подтверждения данные не отправляются.
